# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

Personal dotfiles for one actively maintained NixOS machine plus legacy Arch/Fedora/stow material. **Almost all live work happens in `nixos/`** (a flake, host `nixos`, user `howie`, NixOS 25.11, NVIDIA RTX 2080 Ti, Hyprland). Everything else is either legacy or manual-setup notes. There is no test suite and no CI; "verifying" a change means evaluating/building the flake.

## Commands

Run from anywhere; the flake lives in `nixos/` (the repo root is not a flake).

```bash
sudo nixos-rebuild switch --flake ~/.dotfiles/nixos      # apply (zsh alias: `rebuild`)
nix flake update --flake ~/.dotfiles/nixos && sudo nixos-rebuild switch --flake ~/.dotfiles/nixos   # alias: `update` (bumps ALL inputs)
nix build --no-link ./nixos#nixosConfigurations.nixos.config.system.build.toplevel   # build without activating: the verification step (also runs shellcheck on wrapped scripts)
statix check nixos                                       # Nix linter (installed system-wide); home.nix is clean, remaining W20 "repeated keys" warnings are in configuration.nix and flake.nix (hardware-configuration.nix is generated; leave it)
./nixos/pkgs/update-t3code.sh [--check] [stable|preview|nightly]   # bump the T3 Code AppImage version + hash in pkgs/t3code.nix
```

`nixos/result` (build symlink) is gitignored.

## Architecture

- `nixos/flake.nix` – single `nixosConfigurations.nixos`. Home Manager is wired in as a NixOS module (`useGlobalPkgs`, user `howie` → `home.nix`). Two nixpkgs inputs: stable `nixos-25.11` (default) and `nixpkgs-unstable`, exposed to modules as the `pkgs-unstable` specialArg (NixOS side) and via `inputs` (Home Manager side). Packages deliberately taken from unstable: Sunshine, Quickshell (for DMS), and the DMS flake itself (needs newer Go). Preserve those `follows` choices when editing inputs.
- `nixos/configuration.nix` – system layer: boot/kernel params, SDDM autologin into Hyprland, Tailscale, PipeWire, Syncthing, Steam, Sunshine, a udev rule + script that unmutes a Focusrite Scarlett on plug-in (uses ALSA `numid`s, tied to this exact card/kernel), and a systemd unit that bounces `enp5s0` after resume. Imports `hardware-configuration.nix` and `nvme.nix` (data-disk mounts). `games.nix` and `pw.nix` are imported-but-commented-out/unused.
- `nixos/home.nix` – user layer: zsh/git/gh/direnv/neovim, Hyprland settings, DankMaterialShell (DMS) as the shell/bar/lock, a `t3code` user service, and agent skills.
  - **Skills pipeline**: `skills` is built from flake inputs `poteto-plugins` (only `unslop`) and `mattpocock-skills` (flattening `engineering`/`productivity`/`misc` categories) and symlinked into both `~/.claude/skills` and `~/.codex/skills`. Adding a skill source means editing the `skills` attrset, not copying files.
  - Hyprland config is generated by Home Manager (`~/.config/hypr/hyprland.conf` is a store symlink). `settings.source` pulls in `~/.config/hypr/dms/*.conf`, which DMS generates at runtime and which is **not managed by Nix or tracked here**. Home Manager's Hyprland module also starts `hyprland-session.target` (hence `graphical-session.target`); no manual `exec-once` is needed for that.
  - Keep attribute sets merged (`home = { … }`, `programs = { … }`, `gtk = { … }`) rather than repeating `home.x`/`programs.y` keys; `statix` flags repeats. A pure restructure can be proven a no-op by comparing `nix eval --raw ./nixos#nixosConfigurations.nixos.config.home-manager.users.howie.home.activationPackage.drvPath` before and after.
- `nixos/pkgs/t3code.nix` – wraps the upstream T3 Code AppImage; version and `hash` are rewritten in place by `update-t3code.sh` (sed on the `version = "…";` / `hash = "…";` lines — keep that formatting).
- Remote-gaming stack (spans several files, edit together):
  - `1920x1080.bin` is a dump of the DP-3 monitor's EDID, injected on connector DP-1 via `hardware.firmware` + `drm.edid_firmware=DP-1:…` + `video=DP-1:e` to create a virtual display. It **requires `hardware.firmwareCompression = "none"`** or the kernel gets ENOENT.
  - Hyprland (`home.nix`) uses DP-3 (5120x1440@120) and disables DP-1.
  - `services.sunshine` in `configuration.nix` declares apps; each runs `sunshine/sunshine-res.sh` as prep-cmd. The script is wrapped with `writeShellApplication` (shellcheck at build time, `hyprctl` taken from the system Hyprland, `MON` exported from `streamMonitor` in the same `let`, UID via `id -u`) — change the monitor there, not in the script. It switches that monitor to the client's resolution and restores via `hyprctl reload`, plus a log-tail watcher that restores on Moonlight disconnect (Sunshine only runs `undo` on app quit). `bashOptions = [ "nounset" ]` is deliberate: the script relies on `kill`/`ls` failing without aborting.
  - `nixos/docs/remote-gaming.md` documents this stack: where each piece lives, status, the hard-won gotchas, and open work (headless DP-1, Wake-on-LAN, lock after autologin). Update it instead of adding handoff notes elsewhere.

## Gotchas

- **Flakes only see git-tracked files.** `git add` new/renamed files (including `.bin`, `.sh` referenced via `./path`) before rebuilding, or Nix reports them missing.
- `nixos-rebuild` is required for every change; editing `.nix` and rebooting does nothing. Check kernel params landed with `cat /proc/cmdline`.
- Option names are case-sensitive (`services.displayManager.autoLogin`, not `autologin`).
- Only one DRM-master compositor can own seat0: Hyprland running means `gamescope --backend drm` cannot start, even on another connector.
- `networking.firewall.enable = false` is intentional on this host; don't "fix" it without being asked.
- `README.md` (English) and `README.nl.md` (Dutch) mirror each other; update both when changing either.
- Comments in `configuration.nix`/`home.nix` are a mix of English and Dutch; keep surrounding style when editing nearby.
- Commit messages follow `nixos: <what changed>` for anything under `nixos/`.

## Legacy / non-NixOS (don't assume these are active)

- `nixos_old/` – previous per-host channel-based configs (`biacws01`, `homelab`, `hp`, `system`, `users`), kept for reference while being migrated into `nixos/`. They use `nix-channel`, not flakes (apart from `users/howie/flake.nix`).
- `.config/hypr/` – JaKooLit's Hyprland dotfiles for the Arch/Fedora Framework laptop. **Not used by the NixOS host** (its Hyprland comes from `home.nix`). `rc/`, `nvim/` and `.config/` are laid out to be symlinked with GNU `stow` (`stowrc.sh` first moves existing rc files to `.bak`, then runs `stow -S rc`); `stow` is not installed on the NixOS host.
- `arch.sh`, `fedora*.sh`, `app-neovim.sh`, `arch-bt.sh`, `proxmox.sh` – mostly commented-out checklists of setup steps, not idempotent installers; read before running.
- `bluetooth-dualboot.py` – interactive helper that converts Windows-registry Bluetooth pairing keys into BlueZ `info` format (see `BLUETOOTH.md`, which is rough notes).
- `.git-crypt/` holds a git-crypt GPG key, but there is no root `.gitattributes` and no filter configured, so nothing is currently encrypted.
